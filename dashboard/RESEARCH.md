## 游戏画像聚类（YMT）

入口：`/#research/clusters`。展示五类占比、五张解锁率直方图、三个指标对照、十个标签的富集与覆盖率，以及每类两款热门游戏。图注采用“详情说明”，已按用户要求移除原“怎么看”段落、将“看图说话”改名。原稳健性与方法局限两个折叠区块已移除，页面共 10 张图。手机表格可内部横滑，左侧标签固定；直方图各自标注纵轴刻度，不能直接跨图比较柱高。

标签倍数从 `1.00×` 解释：它表示该标签在本类与全部分析样本中占比相同；高于 1 更常见，低于 1 更少见。采用假设“整体占比 10%”的例子，对照本类 10% / 20% / 5% 分别为 1.00× / 2.00× / 0.50×，避免把倍数误读为玩家比例或实际带标签比例。

正文只改展示名，不改原模型与归属：0=分布较分散、1=中段较集中、2=极低解锁型、3=两头集中型、4=高解锁集中型。原交付的“好玩”“劝退”等体验判断不用于正文类名；PCA 原图保留原标签，并在图下提供与正文类名的对应关系，不把解锁率解释为难度、流程、玩家偏好或弃坑率。

“从点图看分组”一节展示用户指定的 `tier-pca.png` 与 `shape-pca.png`，按原字节复制至 `dashboard/figures/ymt/` 并独立持久化。每图独立解释点、颜色、坐标、分布特点与局限，点击在新标签页打开完整 PNG；手机按宽度缩放。每图抽样 1.2 万款，图例标的是完整类别数量。两图特征空间与颜色分类不同，不能横向按坐标或颜色一一对应；前两轴分别保留约 71% / 49% 的变化信息，不是准确率或玩家偏好分数。

两张图下分别增加“这张图画的是什么 / 横轴 / 纵轴 / 方差百分比”四项说明：坐标是多个指标的综合结果，没有某个原始指标的单位；把全部特征差异视为 100 份，第一张横轴约 57 份、纵轴约 14 份，第二张约 29 份和约 21 份，后者合计约一半（原图分别取整）。未在这两条轴中展开的差异仍存在，不把二维图解释为全部信息。

其后按用户要求补充“主成分 1、2 分别由什么组成”，每图现为五项说明。依据 `result/YMT/cluster.py` 的 `build_full` / `build_shape`：第一图为成就数 log1p、5 项解锁率统计及 4 项占比，共 10 项；第二图为成就数 log1p、3 项形状及 4 项占比，共 8 项，7 项分布指标先扣除对平均解锁率的一元线性拟合值。两者均标准化后进入 PCA，同图两轴使用相同输入、不同权重。原交付只保存解释方差比例、没有保存 PCA 各指标权重，因此页面列输入与处理方式，不猜测具体权重或将某轴等同于单个指标。方差解释补为“数值离平均值有多分散”，再说明百分比为保留差异的比例。

冻结数据在 `cluster-data.json`：从 `result/YMT/cluster-report.json` 提取画像、数量、热门游戏与结构型稳健性，从 `visual.html` 的内嵌 DATA 提取原始直方图数组和标签交叉汇总。两份交付的输入指纹均为 `923685f71ea2`，数据抽取时间 2026-10-17；原 `report.md` 与 `experiments.md` 仍标旧指纹 `6fd8e8990c2a`，本页不采用旧指纹。文件保留输入完整指纹及原交付文件 SHA256，浏览器验收会核对来源摘要和关键数字。

## 实际完成曲线与游戏用户粘性（LYX）

入口：`/#research/retention`。**直接 iframe 嵌入刘宇翔的原始交付页**，不做重绘、不改写原页的选择与口径说明。原页是 5.33MB 的自包含单文件（CSS / JS / 数据 / SVG 全内联，无外部 fetch、无 hash 路由、无 `window.parent` 依赖），放进 iframe 即可完整运行；面板只提供容器和「新标签页 / 全屏」两个出口。

原页不是单文件应用：它用相对路径引用 `../docs/` 与 `../analysis/`，所以面板发布的是**整棵目录树**，不是只搬 `index.html`。`scripts/sync_lyx_bundle.py` 从 `result/LYX` 同步 60 个文件、共 17.1MB 到 `dashboard/lyx/`：

| 类别 | 数量 | 路径 |
|---|---|---|
| 入口页 | 1 | `WEB/index.html` |
| 文档 | 3 | `docs/ANALYSIS.md`、`INSTRUCT.md`、`experiments.md` |
| 正式图 01–21 | 21 | `analysis/T1Core/figures/*.png`（01–15）、`analysis/T2Sum/figures/*.png`（16–21） |
| 来源明细 | 35 | `analysis/**/output/**` 的 CSV / JSON |

只同步「页面真的会点到」的文件，不搬整个 `result/LYX`（那里还有 40MB 的 selections 快照和 trajectory 图，原页没有引用）。脚本会逐个核对显式链接、21 张原图与 35 份来源文件在面板目录里都存在，缺一个就报错。

服务端不用 `http.FileServerFS`：它会把以 `/index.html` 结尾的路径 301 到目录，而这里不提供目录索引，重定向过去只会得到 404。改用 `staticTree()` 自己 `fs.Open` + `http.ServeContent`，目录一律 404。入口 `GET /assets/research/lyx/WEB/index.html` 返回 200 与 5,334,221 字节（与源文件逐字节一致）。

2026-10-20 起，完整原页与附件保留原字节，独立放在服务器 `/opt/achievement-dashboard/content/`；研究图、聚类与趋势汇总 JSON、历史 `analysis-report.json` 也放在这里。只有 UI 继续内嵌，linux/amd64 压缩符号后的二进制约 11MiB。容器只读挂载整个 `content/`，使用 `current` 指向的完整版本；本机从 `dashboard/` 启动默认直接读本目录，或用 `--content-dir` 指定版本目录，URL 与页内相对链接不变。

部署按文件 SHA256 校验服务器对象的实际字节，只有服务器找不到摘要一致的文件时才上传。`objects/` 保存内容，`releases/` 用硬链接组成完整版本，全部文件验证通过后原子切换 `current`。当前路径缺文件或恢复旧版本时直接复用已有对象，零数据上传。普通代码包不含这些数据；旧版本与对象保留，不自动删除。全新空目录首次部署会上传全部内容。只读挂载不等于备份，服务器备份应覆盖此目录。

首次迁移也检查部署目录里已有的 `data/processed/analysis-report.json`，摘要一致则直接在服务器复制，不重传历史报告；对象缺失但当前版本文件完整时也直接本机修复。只检查清单中同名路径，且拒绝越出显式目录的符号链接；复制后再次校验，历史可变文件不会与新对象共用 inode。本机模拟可加 `--legacy-root /旧部署目录`。

## 运行边界

Go 只代理三个 GET 接口：`/api/research/recommendation/meta`、`search`、`recommend`。响应保留原算法排名、解释、数据与算法版本。点评 POST 不在本次接入范围；原补抓 POST 仍返回 404。服务未启动或失联时，成果页显示提示并支持重试，其他面板功能照常工作。

集成入口 `dashboard_service.py` 使用当前源码生成的图谱绑定与完整校验；原 `run.py` 还会检查交付包 `reports/source-map.json` 的文件字节摘要。交付文件格式变化会使原入口拒绝运行，不能把旧交付摘要视为当前集成版本的校验结果。本次没有改写交付包摘要或推荐算法。

生产环境仍使用纯 Go / scratch 面板镜像。`bash result/ZZY/deploy.sh` 单独部署推荐容器，`bash dashboard/deploy.sh` 单独部署面板。两者读取 `dashboard/.env`，面板只接收 POSTGRES_* 与推荐连接 HOST/PORT；推荐容器另从本机 `result/WWH/5/.env` 接收DeepSeek配置，SSH凭据留在本机。服务器 `/opt/achievement-recommendation/runtime` 绑定到容器 `/runtime`，普通部署与重启直接复用；仅 `bash result/ZZY/deploy.sh --refresh-data` 显式更新数据。详细配置与仅打包模式见 [推荐部署说明](../result/ZZY/deploy/README.md)。
