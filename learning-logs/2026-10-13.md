## 这次踩到的坑

- 2025 年标签覆盖率只有 34.4%、2024 年 82.3%，且 2021 年起逐年下滑。一开始按「抓取还没跑完」理解，去查 `fetch_tasks` 才发现 SteamSpy 任务 99% 以上是 `ok`——**缺口在数据源侧**（SteamSpy 对近年游戏不返回标签），方向差点搞反。
- 缺失还高度非随机：2024 年无标签的游戏里 58% 是免费游戏，而有标签的游戏里只占 4.1%。所以必须把「是否剔除免费游戏」当敏感性检验跑一遍；好在两套口径的曲线几乎重合，趋势不是免费游戏缺失造成的。
- 每款游戏的平均标签数从 2017 年的 10.92 涨到 2024 年的 17.79。标签密度整体上行会让多数标签占比被动抬高，只看涨幅会误读成「这个类型越来越受欢迎」。
- 折线图原本把终点数值直接标在曲线尾端，多条线在 40–50% 区间汇聚时全叠在一起，改成把数值并进图例才干净。类目演变图去掉「玩法类型」后，右上角 81% 与 80% 又叠了一次，同样并进图例解决。
- 把脚本移到 `result/YJH/` 之后，`uv run python -m modeling.tag_trends` 直接失效；而且它原本靠 `parents[1]` 定位项目根、靠 `cwd` 找项目包，换目录就全坏。改成「向上查找 `pyproject.toml`」定位根目录并自行补 `sys.path`，归档位置也能照跑——**移动 Python 脚本前先确认它怎么定位项目根，否则必坏**。
- 最要紧的一条：标签是 2026 年抓的「现今标签」，不是当年标签。库中没有当年的玩家数、销量或评论历史，**不能据此判断某游戏在当年是否流行**；2026 年尚未结束，其年度数量也不可与完整年份直接比较。

## 后续追加：面板改为 Go 单文件并部署到腾讯云

### 做了什么

- 把 `dashboard/` 后端从 Python（标准库 `http.server`）改写为 **Go 只读服务**，前端三件套用
  `//go:embed` 打进同一个二进制；**补抓功能整体删除**（数据已抓完，`fetch_tasks.pending = 0`），
  路由、前端按钮、Python 写路径一并去掉。依赖只有 `github.com/jackc/pgx/v5`，并用
  `go mod vendor` 把源码入库，构建全程离线不下载。
- 部署改为纯脚本：`bash deploy/deploy.sh` 在本机交叉编译 linux/amd64 → 上传二进制 +
  Dockerfile + compose + 分析报告到服务器 `/opt/achievement-dashboard/` →
  `docker compose up -d --build`。**服务器上不需要仓库、不需要 Git、不需要 Python**。
- 镜像 `FROM scratch`，最终 **16MB**（原 Python 版约 2GB），容器内存约 6MB，构建秒级。
- 面板已上线：`http://82.157.208.173:8600`。线上限速（60 次/分钟/IP）实测生效，
  超限返回 429 + `Retry-After: 60`，且限速期间静态页仍正常（只限 `/api/*`）。

### 为什么改（下面的数字都是实测的）

原 Python 版为了拿 `REPORT_PATH` 一个常量，导入了 `modeling.regression.dataset`，而那个模块顶层
`import numpy/pandas`，于是 pandas、scipy、scikit-learn、shap、numba(53MB)、llvmlite、
matplotlib、seaborn、plotly 整套科学计算栈全被拖进运行镜像。实测 wheel 下载约 600MB、
2 核服务器上构建超过 11 分钟。**一个字符串常量换来 600MB 依赖**，这是重写的直接动因。

### 验证方式：黄金对比

移植最怕静默偏差，所以先把 Python 版 6 个接口的响应存成基线，再逐字段递归比对 Go 版输出
（含 63+12 条成就的 NUMERIC 百分比、`TEXT[]` 数组、NULL 语义、447 条标签）。最终只剩 3 处
差异，全部是有意删掉的 `fetching` 字段。另外复用现成的
`scripts/check_dashboard_browser.py` 做浏览器验收（它与后端语言无关），一次通过、
`page_errors: 0`。

### 这次踩到的坑

- **pgx 解 timestamptz 返回的是本地时区**（内部走 `time.Unix`）。不显式 `.UTC()` 的话，同一
  时刻在不同 TZ 的机器上会渲染成不同偏移——本机输出 `+08:00`，而 Python 是 `+00:00`。
  前端用 `new Date(...)` 显示不受影响，但两个后端给出不同字符串是没必要的隐患。已归一化，
  并用 Asia/Shanghai、UTC、America/New_York 三个时区各起一次服务确认输出一致。
- **公网打不开时的症状极具误导性**：`curl` 报「Connected 然后 Empty reply」，看着像服务崩了，
  实际是腾讯云安全组没放行。证据链：`tcpdump -i eth0 port 8600` **一个包都没抓到**（包根本
  没到主机），而对照组 4396 端口抓包正常、公网 200；主机私网 IP 是 `10.2.0.2`，前面有网关
  做 NAT 与安全组。**遇到这个症状先查控制台，别改代码。**
- dashboard 原来**每个请求都新建一个 SQLAlchemy Engine**（每个自带 5+5 连接池），并发下把
  共享云库的连接数打满（`FATAL: sorry, too many clients already`），面板直接 500。Go 版改为
  全程共用一个池、上限 4。这是部署前压测暴露出来的既有缺陷，与用什么语言无关。
- 后台跑镜像构建时 SSH 一断，BuildKit 就把构建标成 `CANCELED`。**长构建放服务器上的 tmux
  里跑**，别挂在本地 ssh 会话上。
