### 配置项改成「服务器地址」与「PostgreSQL 地址」两项分开填

- 一个绕不开的点：`POSTGRES_HOST` 在本机跑面板时要填公网地址、在容器里必须是 `127.0.0.1`。
  一开始的做法是「`.env` 里填什么不管，部署脚本偷偷把 HOST 改写成 `127.0.0.1`」——
  **这个隐式改写过了一轮就被要求去掉**：文件里写的和实际用的不一致，排查时最容易被误导。
- 改成 `DEPLOY_HOST`（服务器地址）与 `POSTGRES_HOST`（数据库地址）**两项各自独立填写、
  原样使用**，脚本只做「抽出 `POSTGRES_*` 传上去」这一件事。
- 本机预览改用环境变量临时覆盖（`POSTGRES_HOST=82.157.208.173 go run .`），环境变量优先于 `.env`。
- 顺带在启动日志里打印实际连的库（`数据库：host:port/db`，不含密码），两种跑法下都能一眼
  确认填对没有。实测：不覆盖时日志显示 `127.0.0.1` 且请求 500（本机没有库），覆盖后走公网
  地址正常——这就证明了值确实被原样使用。
- **教训：配置项宁可多一个，也不要让同一个键在不同环境下含义不同——那等于把「必须读代码
  才知道」的成本塞进配置文件。**
- `--report` 改成留空时按候选路径自动找（容器内 `data/processed/…`、本机 `../data/processed/…`），
  并把选中的路径打进启动日志。否则本机从 `dashboard/` 跑和容器里跑得传不同的路径参数。

## 遇到什么坑

- **Expect 的 `spawn` 不会把 Tcl 列表展开成多个参数**：`spawn scp [split $files] target:/dir/`
  会把整个列表当成一个带空格的文件名传给 scp（报 `stat local "a b c": No such file or directory`）。
  改成「本地打成一个 tar → 只传单个文件 → 远端解包」，顺带把报告也装进去，
  全程只需一次 scp、一次密码应答。
- **macOS 的 `tar` 会给带扩展属性的文件附加 `._*` 的 AppleDouble 文件**，传到服务器上就是
  部署目录里多出一个 163 字节的 `._achievement-dashboard`。加 `COPYFILE_DISABLE=1` 关掉。
- **提交前先看文件体积**：那个 100.9 MiB 的 sqlite 在 `git status` 里只是一行路径，
  不点开根本看不出它会让 push 失败。以后往仓库里加 `result/` 下的产物前先 `du -sh`。
