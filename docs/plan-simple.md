# 一页看懂：我们这个项目在干什么

> 完整版见 `docs/plan.md`，这份只是大白话版。

## 一句话

**扒 Steam 的数据，回答一个问题：玩家更愿意玩什么样的游戏？**

## 问题怎么变成能算的东西

"愿意玩"是个感觉，没法直接算。所以我们换成几个能数的数：

- 玩了多少小时
- 成就解锁了多少（完成得多 = 玩得深）
- 还在不在玩（最近有没有上线）
- 有没有拿全成就

这几个数高，就说明这游戏玩家"愿意玩"。

## 分两步

**第一步（Q1，打辅助）**：算清楚每个成就到底有多难。
用 IRT 模型，同时算出"成就有多难"和"玩家有多强"。另外 Steam 官方有一个"全球有多少人解锁了这个成就"的数据，可以拿来对照，看我们算得准不准。

**第二步（Q2，是正题）**：找出什么样的游戏玩家更愿意玩。
拿上面那些"愿意玩"的数当答案，用游戏的属性去解释它——类型、价格、标签、热度、难度结构。用 XGBoost 之类的模型 + SHAP 看每个属性贡献了多少。

## 数据从哪来

全是 Steam，四个来源：

| 来源 | 拿什么 |
|------|--------|
| GetOwnedGames | 玩家游戏库、玩了多少小时 |
| GetPlayerAchievements | 每个成就解锁没、什么时候解锁 |
| GetGlobalAchievementPercentages | 全球完成率（当难度用） |
| appdetails + SteamSpy | 游戏名字、类型、价格、标签、成就真名 |

## 一个容易踩的坑

两个接口给的成就名字都是**内部代号**（比如 `NEW_ACHIEVEMENT_1_1`），真正的名字在另一个字段里（比如 `A Hero Emerges`）。所以清洗的时候要拿代号做关联，把真名接上，给每个游戏生成一份标准成就文件。后面所有分析和报告都用真名。

## 最后要交出什么

- 爬虫代码 + 清洗流程
- 每个游戏一份标准成就文件
- Q1 的难度分析结果
- **Q2 的结论：玩家更愿意玩什么样的游戏**
- 实验记录 + 最终报告和图表

## 必须说清楚的局限

- 只爬得到**公开档案**的玩家，这些人本来就偏硬核，结论会有偏差
- 解锁时间只有**天**的精度，看不出具体几点玩的
- SHAP 只能说明"模型觉得这个特征重要"，**不能当成因果**
- SteamSpy 的销量是估算值，不能当准确数
