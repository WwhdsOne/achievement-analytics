# 磁盘推荐与持久成果部署实施计划

> **For agentic workers:** 使用并行子任务分别实现 Rust 查询与解释、面板持久资源、真实接口验收；主代理整合导入、服务与部署。遵循用户要求：只在 main 工作，不新增测试用例，不提交或推送，不改原 Python 服务。

**Goal:** 新建独立 Rust 推荐服务，数据长期存磁盘、请求按需查询；面板成果资源按摘要增量同步。

**Architecture:** `result/ZZY/rust-recommendation/` 使用 SQLite 保存游戏、实体、关系与来源 JSON，服务只读打开数据库，限制页缓存、关闭 mmap，逐候选评分、只保留 Top K。独立导入命令流式读取既有冻结快照与 JSONL，校验摘要后原子发布数据库。原 Python 入口及部署完整保留。面板资源从服务器持久内容目录提供，部署比较实际文件摘要，仅上传缺失或变化文件。

**Tech Stack:** Rust / rusqlite bundled SQLite / serde_json / tiny_http；现有 Go 面板与 Docker / Python 标准库部署辅助。

## 验收目标

- 原 Python 文件与既有部署行为保留；新目录包含 Cargo.lock、源码、文档、独立部署入口与 Dockerfile。
- Rust meta/search/recommend 保持面板所需字段、中文搜索、资格说明、1–3 种子、年份先筛、分数与来源解释；版本如实标注 Rust 实现。
- 固定同一快照，真实比较 Python / Rust 的排名、分数、解释关系、事实路径与贡献，不以“能返回 JSON”代替一致性。
- 持久数据库在请求时只读；启动不查云库、不重建图谱；缺失或损坏明确失败。导入与普通程序部署分离，同摘要数据库不重复上传。
- 实跑 Rust Docker，记录空闲与真实请求峰值、镜像和启动耗时；说明与原 Python 同架构基线的可比范围。
- LYX 原页、附件和链接保持；模拟首次、重复、单文件变化与损坏的同步，证明重复同步数据传输为零。
- 完成真实 Go 编译、相关浏览器脚本、Rust release 编译、部署 prepare-only 和 diff 检查；无云端发布。
