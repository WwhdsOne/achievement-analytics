# 1. 按发售年份分析游戏类型演变（原③）

当前数据可以研究「按发售年份的类型演变」；历史大众热度需要历史数据。

最直接的指标是：

$$S_{t,y}= \frac{\text{年份 }y\text{ 中含标签 }t\text{ 的游戏数}} {\text{年份 }y\text{ 中具有有效标签的游戏数}}$$

它表示某年发行的、已覆盖标签的游戏中，某类游戏占多少。多标签游戏可以重复计入不同类别，因此各标签占比不一定加总为 100%。

可以展示标签占比折线图、年度热力图，以及增长最快的类型。同时报告各年份的标签覆盖率，避免把数据缺失当成类型变化。

需要注意，**「2018 年发行的游戏，现在拥有量很高」并不能证明它在 2018 年就很热门。** 要研究真正的「当年玩家潮流」，需要当年的玩家数、销量或评论等历史记录。另外，2026 年尚未结束，年度数量不能直接与完整年份比较。

# 2. 游戏画像聚类与自动分型（新⑥）

让数据自动发现游戏之间的共同特点。原来的方向是「根据已有标签分析游戏」，这里可以进一步问：

> 同样属于 RPG 的游戏，它们的成就完成结构是否存在不同类型？

为每款游戏提取这些特征：

| 特征组   | 可以计算的指标                     |
| -------- | ---------------------------------- |
| 游戏类型 | 标签的多热编码或加权向量           |
| 成就规模 | 成就总数                           |
| 解锁分布 | 解锁率均值、中位数、不同分位数     |
| 稀有成就 | 解锁率低于 1%、5% 的成就占比       |
| 普及成就 | 解锁率高于 50%、80% 的成就占比     |
| 游玩投入 | 平均时长、中位时长，前提是字段有效 |

先做数值标准化，再用 K-Means 尝试不同聚类数量，结合轮廓系数和人工检查确定分组。

可能形成「多数成就容易达成型」「少量普及成就＋大量稀有成就型」等类别，**这些名称要根据实际结果归纳，不能事先当作结论。**

最终可以展示游戏分布图、各类特征对比，以及每类的代表游戏。这里聚类的是**游戏的群体完成特征**，并不能据此直接认定玩家分成了哪些人群。

# 3. 主线进度漏斗与成就参与分析（原①）

把「用户粘性分析」具体化为「主线进度漏斗 + 成就参与程度」。

先选 100～1000 款主线明确的游戏，人工确认「入门—前期—中期—后期—结局」的关键成就，再按剧情顺序画出各节点解锁率。

设入门成就解锁率为 $p_s$，结局成就解锁率为 $p_f$。在**结局必然要求先完成入门节点、统计口径一致且 $p_s>0$** 的情况下，可以计算：

$$\text{观察时点内入门者的通关比例}=\frac{p_f}{p_s}$$

例如入门率 80%、结局率 32%，对应比例为 40%。这是一个**假设示例**，不是实际结果。

但中间没有完成的人，可能还在玩，也可能已放弃，所以它不能直接等同于流失率或留存率。

另外，**每项成就的全球解锁率，不能直接推出「全成就玩家占比」**。Steam 官方区分了全球成就比例接口和个人成就接口。若有 $n$ 项成就：

$$\frac{1}{n}\sum_{i=1}^{n}p_i$$

算出的是**平均成就解锁率**。真正全成就比例只能确定上界：

$$P(\text{全部解锁})\leq \min_i p_i$$

要得到准确比例，需要个人解锁记录，或经过核实、确实代表全部完成的专门成就。

# 4. 游戏知识图谱与可解释推荐（新⑦）

最契合「知识工程」的新增方向。已有大量游戏标签关系，很适合建立结构化关系：

| 实体关系             | 数据来源           |
| -------------------- | ------------------ |
| 游戏—具有标签—标签   | `game_tags`        |
| 游戏—包含成就—成就   | `achievements`     |
| 游戏—由其开发—开发商 | 商店详情，若已保存 |
| 游戏—属于类型—类型   | 标签归类结果       |
| 游戏—相似于—游戏     | 计算产生           |

基础版不需要用户历史记录。让用户选择两三款喜欢的游戏，就能生成推荐。

具体做法：将标签转换为向量，对「动作、冒险」等常见标签适当降权，对更有区分度的标签增加权重，再计算游戏相似度。随后增加发行年份、成就画像等筛选条件。

推荐结果要解释清楚，例如：

> 推荐这款游戏，因为它与你选择的游戏共享「回合制、牌组构建」等标签，且成就解锁分布相近。

工程上先做标签相似度推荐，再把关系组织成图谱；每款游戏只保存少量最相似邻居，前端展示当前游戏附近的关系即可。

**验证方式**：抽取一批种子游戏，对比「简单标签重合」与「加权标签推荐」，让同学盲评前五条推荐的相关性。这比只展示一张漂亮关系图更有说服力。

# 5. 分类完成曲线与 RAWG 对比（原②）

游戏标签归类和成就节点标注要**分开做**，RAWG 对比取决于具体字段。

标签方面：已有大量玩家标签，覆盖约 4.13 万款游戏，可以先整理成「玩法、题材、表现形式、单人/多人」等维度，不必重新给所有游戏从零打标签。

完成曲线需要另一套标注：给**成就**标注「主线、支线、收集、挑战、联机、DLC」等类别，并为关键主线节点确认顺序。可以采用「关键词规则或模型辅助初标 + 人工复核」，先做好重点游戏。**不能把所有成就按解锁率从高到低排序，就称为剧情完成曲线**——那样只能得到成就解锁率分布。

RAWG 方面：如果只保存了评分和评价分布，就还不能比较通关率。需要确认是否保存了 `added_by_status`，以及其中是否有 `beaten`、`playing`、`dropped` 等状态数据（官方接口确实列有该字段）。

即使这些字段齐全，RAWG 用户填写的状态与 Steam 成就解锁也属于不同人群、不同口径，适合比较整体趋势和排序，不能把两者差异直接判定为某个平台「算错了」。

# 6. 游戏口碑预测与关联因素分析（新⑨）

增加一个完整的机器学习实验。可以把问题设为：

> 根据游戏标签、发行年份、价格等属性，能在多大程度上预测其当前口碑？

优先使用有足够评价量的 RAWG 游戏子集。RAWG 官方接口提供评分、评价数量等字段，但是否已保存到表中需要确认。

建议先做评分回归：

1. 输入标签、年份，以及实际已有的价格、开发商等字段。
2. 以评分作为预测目标，设置最低评价数量要求。
3. 比较「直接预测平均分」、线性模型和随机森林。
4. 用 MAE 衡量误差，再用特征重要性解释模型。

**训练集和测试集要避免同一游戏不同版本重复出现。** 如果数据允许，可进一步按系列或开发商分组划分。评价分布等直接决定目标评分的字段，也不能作为输入。

这个方向可以检验标签和画像是否具有解释价值，但结果应表述为「与口碑相关」，不能说某个标签「导致」高评分。使用当前快照做出来的也是**当前**口碑预测，不能包装成已经验证的上市前预测。
