## 拉取后开箱即用：核验结论

**同学更新项目后，用启用JavaScript的现代浏览器打开[WEB/index.html](WEB/index.html)，即可使用现有六项任务的核心交互。无需额外传递或连接WWH/LYX两份SQLite，无需安装Python科学计算环境、配置API key或启动分析后端，也不必先运行build或prepare。**

在仓库根目录执行`git pull origin main`后，打开`result/LYX/WEB/index.html`即可。如需通过HTTP同时访问完整报告、原图和来源文件，以`result/LYX`为静态服务根，访问`/WEB/index.html`；具体本机预览命令见[WEB说明](WEB/README.md)。单独复制HTML仍可使用核心交互，附加文件入口则需保留对应LYX目录结构。此处的开箱即用指本地浏览和静态托管，不表示已经自动接入组长网站或公网发布。

数据链路是：**原数据库 → 离线Python分析 → T1/T2结果CSV与来源清单 → build.py打包 → HTML内嵌数据、脚本和样式 → 浏览器交互**。CSV保存的是已计算的分析结果；成品HTML已经包含展示所需数据，浏览时连外部CSV也不需要重新读取。选择游戏、分组、切换口径是在浏览器中筛选和重绘，相关系数、Bootstrap区间、类型汇总和同类参照统计采用预计算结果；浏览器只做分组、中位参考线、坐标与单位换算等展示计算。

2026-10-19交付核验以远端`main`的`21f25b8`为快照，网页实现提交为`da50592`。核验结论如下，区别于此前网页设计阶段的28项检查：

- 直接核对远端Git对象，确认12份WEB文件、T1/T2共157份正式output文件及01～21号正式图均已上传；33份网页来源文件的原生Git内容与网页清单指纹一致，未把“本机存在”误当成“远端已提交”。
- 从远端提交建立不含两库、T0基线缓存或delivery/package的干净副本，6组浏览器检查通过，覆盖默认背景、五款分组、时长参考、评分来源、同类条件和缺失处理；57个报告、原图及来源文件入口实际HTTP访问均为200。
- 保留Git原始LF换行的干净副本可直接运行WEB构建与只读核验，无需任一数据库。Windows自动转CRLF的副本仍可正常使用成品HTML，但重新构建/指纹核验会被换行差异拦截。

| 使用范围 | Git拉取之外的条件 |
|---|---|
| 使用现成HTML、部署当前核心交互 | 无额外数据依赖；完整附件保留LYX相对目录 |
| 修改页面并重新构建/核验 | 已提交源码、26张CSV和7份manifest；无需数据库，跨机需处理换行一致性 |
| 原Python查询、重新绘图或完整复算 | 依入口需要准确WWH快照及LYX时长库，另需相应基线与来源审计；不能等同于网页开箱即用 |

原Python复算仍有已定位的兼容事项：WWH同名库须核对冻结SHA；T0的metrics/verification未进Git，旧verification包含本机绝对路径，目标机应重新生成；20张SVG历史指纹依赖CRLF，部分下游父manifest记录也未同步。补齐两库后，已实测在目标目录重新生成T0并重建198款指标成功，但这不代表全部旧分析入口均已修复。这些问题不阻塞现成HTML的使用。数据更新也不会自动进入网页，需在离线分析完成后重新导出并构建。

当前交付状态：**分析与网页交付完成，待整站部署验收**。数据库单独交接用于后续复算，不是部署现成网页的前置条件；本轮干净副本的浏览器实测采用本机HTTP，未通过内置浏览器直接验收file://离线模式。
