# 玩到哪里 · LYX 交互项目简报

这个目录把已有六项分析整合为一页可阅读、可选择游戏对比的项目简报。页面以“玩家愿意玩到哪里”为主线，展示主线指标、玩法分组、完整过程、游玩投入、口碑关系和同类参照。

**直接打开 [index.html](index.html) 即可使用。** CSS、JavaScript、展示数据和 SVG 图形均内嵌在同一文件中，核心内容不依赖网络、数据库或额外服务。当前交付是本地静态页面，**尚未部署到公网**。

## 2. 打开与本地预览

### 直接离线打开

在资源管理器中双击 `index.html`，使用现代浏览器打开即可。开启 JavaScript 后，游戏搜索、图表切换、节点查看与下载均使用内嵌数据完成。

只复制 `index.html` 到其他文件夹或电脑，核心展示仍然可用；“完整分析报告”“使用与读图指南”“实施与实验记录”等链接是相对仓库目录的链接，需要一起保留以下结构：

```text
result/LYX/
├─ WEB/
│  └─ index.html
└─ docs/
   ├─ ANALYSIS.md
   ├─ INSTRUCT.md
   └─ experiments.md
```

浏览器对 Markdown 文件的显示方式不同，链接可能直接显示文本或下载文档。原报告中的其他图表和数据链接，还需要保留对应的 `analysis/` 目录。

### 用本地HTTP服务预览

推荐以 `result/LYX` 作为服务根目录，而不是只托管WEB，这样 `../docs/` 的完整文档链接才能在服务内解析。在仓库根目录执行：

```powershell
uv run --frozen --no-sync python -X utf8 -B -m http.server 8765 --bind 127.0.0.1 --directory result/LYX
```

然后在浏览器打开：

```text
http://127.0.0.1:8765/WEB/index.html
```

若终端已位于 `result/LYX`，执行：

```powershell
uv run --frozen --no-sync python -X utf8 -B -m http.server 8765 --bind 127.0.0.1 --directory .
```

只在WEB目录启动服务或只托管 `index.html`，仍支持全部核心交互，但 `../docs/` 会超出服务根目录；需要保留并托管相应的LYX目录结构，完整文档链接才能成立。

预览期间终端会持续运行；结束时在**启动这个服务的终端按 Ctrl+C**。如果8765已被占用，可同时将命令和浏览器地址改为其他空闲端口。本地预览只监听本机回环地址，不代表已经完成公网部署。

## 3. 页面怎么用

### 游戏选择与联动

页面默认选择：

- `367520`：Hollow Knight；
- `812140`：Assassin's Creed® Odyssey。
- `1903340`：光与影：33号远征队。
- `1593500`：God of War。
- `1245620`：艾尔登法环。

选择器只搜索当前198款有效主线游戏，支持 AppID、英文名及结果表中已有的中文名，不会联网补全或临时拉取新游戏。最多选择5款，保持选择顺序；点击已选游戏右侧的“×”可以移除。

“试试”按钮继续保留原案例快捷选择；默认预选五款使用上方清单。开场固定使用 Splinter Cell Blacklist 与 Dead Cells，点击“用这两款继续探索”可将它们载入后续分析。

选择游戏会更新对比、高亮和信息卡，**不会把总体统计重新缩小为所选游戏**。例如选择两款游戏后，时长背景仍是69款，口碑四象限仍是183款。清空选择后，总体背景、固定案例和统计继续保留，对比区域提示重新选择。

图中背景点可以点击加入选择；有提示信息的图形可通过鼠标悬停或键盘焦点查看数据。页面顶部可“打印简报”，浏览器打印对话框也可另存PDF；PDF保存的是静态视图，不包含交互能力。

### 六项任务的展示

| 任务 | 页面提供什么 | 主要操作 |
| --- | --- | --- |
| 1. 主线指标 | 首、中、末节点覆盖及前段、后段、全程推进比；原节点名称与可用描述。 | 切换“节点覆盖／阶段推进”，查看1—5款游戏的柱状对比与节点卡片。 |
| 2. 玩法差异 | 主类型与完整多标签的阶段推进中位数、游戏数及已有区间。 | 切换两种分组口径，点击类型查看成员和所选游戏的位置。 |
| 3. 完整过程 | 选中游戏的完整节点序列、归一化曲线和相邻区间落差。 | 切换到“完整节点过程”，修改每组款数或组数。 |
| 4. 游玩投入 | 平均游玩时长相对主线、主线＋支线、全收集参考耗时的三种比值，与全程推进对照。 | 切换参考目标；所选游戏在固定69款背景中高亮。 |
| 5. 口碑关联 | Steam四象限、前后段关系与共同142款的三种评分比较。 | 切换视图、阶段或评分来源，点击象限展开游戏成员。 |
| 6. 同类参照 | 目标游戏相对相似玩法参照的中位数差、各阶段差、参照数量及完整名单。 | 切换Jaccard阈值、好评接近或长度接近条件，展开参照成员。 |

### 完整过程的分组规则

“完整节点过程”默认按**每组2款**分图。选择5款时，依次输出 `2＋2＋1`，最后不足一组也正常展示。每组款数可设为1—5。

切换为“组数均分”时，参数表示希望分为多少组，按当前选择顺序尽量均分。例如5款分2组时为 `3＋2`，分3组时为 `2＋2＋1`；组数多于所选游戏数时，每款各成一组，不生成空组。

### 缺失状态

各专题资格独立判断，无法使用某项数据的游戏仍保留在选择中：

- 15款只有两个有效节点：首、末覆盖和全程推进可用，中节点、前后段为空。
- 不属于69款时长共同样本：显示缺少的有效时长条件，不绘制零值点。
- 不属于142款共同评分样本：评分来源对比中不绘点，但保留选择及可用信息。
- 同类参照少于5款：显示真实参照数，不计算参照中位数、差值和百分位。
- 节点描述只采用已导出结果表中的原文；空缺保留，不生成补充描述。

“看看缺失如何处理”示例包含 God of War（RAWG时长缺失）、DOOM（仅两个节点）、Clustertruck（主条件4款参照）与 Session（主条件0款参照）。

所选游戏指标可在“这几个指标，应该怎样理解？”中下载为CSV，空值保留为空；这项下载仅发生在浏览器本地，不会写回分析结果。

页面末尾另有按六项任务整理的21张原图入口，以及可打开的来源文件清单。原图是已有固定案例，不随当前选择更新；这些外部文件入口需要保留LYX目录结构。

## 4. 重新构建

已有 `index.html` 可以直接查看。修改页面源码或更新冻结分析结果后，才需要重新构建。

从**仓库根目录**执行：

```powershell
uv run --frozen --no-sync python -X utf8 -B result/LYX/WEB/build.py
```

从 **`result/LYX` 目录**执行：

```powershell
uv run --frozen --no-sync python -X utf8 -B WEB/build.py
```

脚本通过自身位置定位LYX，不依赖终端当前目录。构建过程为：

1. 读取已有分析CSV与manifest，校验消费结果表的自身输出哈希。
2. 核对样本集合、主线中位节点与比值关系、时长比值、参照成员及数量。
3. 整理内嵌数据，读取页面模板、CSS与JavaScript，生成真实案例首屏SVG。
4. 在本 `WEB/` 下写入 `index.html` 与 `source_manifest.json`，终端输出文件位置、大小及样本数量。

Python适配与构建代码只使用标准库，不新增项目依赖。`--frozen --no-sync` 表示沿用当前锁定环境，不在本次命令中同步安装依赖；本机仍需先具有项目的uv环境。命令中的 `-B` 避免生成Python字节码缓存。

**构建程序的写入边界仅为WEB目录。** 不修改原SQLite、分析CSV、图片、历史manifest或进程状态，不触发远端数据库、DeepSeek、其他模型或数据API。数据更新应先由原分析流程产生经审核的新结果，再重新构建网页；网页不是数据采集或统计重跑入口。

构建后，可在仓库根目录执行只读交付核验：

```powershell
uv run --frozen --no-sync python -X utf8 -B result/LYX/WEB/verify.py
```

核验会检查网页源码及成品指纹，并从结果表重新读取数据，与HTML内实际嵌入的内容逐项比较。它不启动浏览器，不修改产物，也不重新计算原统计。首次施工的本机保护基线位于已忽略的`runtime/protected_before.json`；只有保留该基线的机器才可额外传入`--check-protected`。`runtime/`中的预览辅助页、截图及本机记录无需提交。

## 5. 冻结数据与来源

页面使用的数据库版本标识为：

```text
wwh5-2026-10-13T10:26:09.722887+00:00
```

这是数据快照版本，不是页面访问时间。页面生成时间和版本在页面底部、来源区及 `source_manifest.json` 中记录。

| 样本 | 数量 | 含义 |
| --- | ---: | --- |
| 有效主线曲线 | 198款 | 按既有质量规则筛出的主线分析范围。 |
| 完整三节点 | 183款 | 首、中、末节点及前后段推进可计算。 |
| 三种参考耗时共同样本 | 69款 | 完整三节点，且RAWG平均游玩时长及三种HLTB参考耗时有效。 |
| 三种评分共同样本 | 142款 | Steam、Metacritic、RAWG评分同时有效，用于同样本评分比较。 |
| 主条件有效同类参照 | 181款 | 183款目标中，主条件下至少有5款参照，可计算相对统计。 |

这些数字对应不同资格，不能互相替代或相加。类型、口碑和同类的基本目标集使用183款；时长固定69款；三种评分比较固定142款；切换同类条件会改变有效参照数量。

### 来源核验边界

历史分析manifest中的父级核心manifest指纹存在不同步记录。适配器会把它们明确记录为 `parent_manifest_fingerprint_drift`，保留记录值、现值和目标路径，不静默修复历史文件。

这与消费结果表本身的完整性分开处理：构建时会要求实际使用的CSV与其所属manifest的输出哈希一致，并复核样本和数值关系。结果CSV缺少所属输出记录、哈希不符，或关键样本与数值关系不一致时，构建会报错停止。父级清单的历史漂移则作为元数据警告显式保留。

因此，页面可说明其所使用结果表已经执行这些检查，不能宣称全部历史审计链已经完全同步。详细历史情况继续以 [ANALYSIS.md](../docs/ANALYSIS.md) 和 [experiments.md](../docs/experiments.md) 为准。

## 6. 指标与结论的解释边界

- 本研究观察热门1000款冻结游戏中的可用子样本，是游戏级成就聚合快照，不能直接解释为真实玩家留存、流失或因果效果。
- 中节点按有效剧情序列的数组位置选取，偶数取靠前中位；它不是时间中点。多结局采用已定义的代表末节点，不累加结局覆盖。
- 同一游戏的前段×后段＝全程；不同游戏集合的各列中位数不能直接相乘或互除。
- RAWG playtime按项目约定作为平均游玩时长；与HLTB参考耗时来自不同统计群体，比值不等于个人完成百分比。
- Steam好评率采用现有结果中的 `positive/(positive+negative)`。不同评分平台的人群、尺度与采集时间不同。
- 类型完整多标签可重叠，成员数不能相加。相关系数及Bootstrap区间沿用原结果，浏览器不重新估计相关或区间。
- 同类参照按玩法相似度等已保存条件确定，不以推进结果挑选；参照Q1—Q3表示游戏之间的分布，不是置信区间。
- 重点案例人工审核已由WWH完成，依据2026-10-17刘宇翔的明确确认；不扩大为全部198款逐项审核。源CSV中的历史审核状态予以保留。
- 页面没有生成统一“用户粘性评分”、游戏质量排名或个体推荐。

## 7. 交接方式

只需演示时，交付 `index.html` 即可；它包含核心六项任务及1—5款游戏交互。需要复查来源时，同时提供 `source_manifest.json`。需要修改并重新构建时，保留本目录源码及上文列出的T1、T2冻结输出文件。

需要让完整报告、指南和原图链接一起可访问时，应保留仓库目录结构，或由部署方把相应文档与分析产物一并发布。页面内的RAWG回链保留用于来源注明。

页面没有后端、写接口、在线API或用户数据持久化；刷新页面会恢复默认选择。后续若由组长整合到已有网站，可直接托管静态页面，或复用适配器与展示组件，但应继续保留固定样本、缺失状态和来源说明。
