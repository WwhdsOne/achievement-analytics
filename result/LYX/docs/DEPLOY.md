### 1.1 打开、预览和构建

成品可用普通浏览器打开[WEB/index.html](../WEB/index.html)。推荐从**仓库根目录**执行以下本机预览命令，以LYX为服务根保留文档、原图和来源文件相对路径：

```powershell
uv run --frozen --no-sync python -X utf8 -B -m http.server 8765 --bind 127.0.0.1 --directory result/LYX
```

访问`http://127.0.0.1:8765/WEB/index.html`；用完在启动服务的终端按Ctrl+C。本机预览只监听回环地址，不代表公网部署。只托管WEB或单独复制index.html可以使用核心交互，但上级docs、analysis附件无法通过该服务访问。详细目录、操作和离线限制见[WEB/README](../WEB/README.md)。

修改WEB源码或替换经过核验的冻结结果后，从**仓库根目录**执行：

```powershell
uv run --frozen --no-sync python -X utf8 -B result/LYX/WEB/build.py
uv run --frozen --no-sync python -X utf8 -B result/LYX/WEB/verify.py
```

build仅写WEB成品及来源清单；verify只读比较源码/成品指纹和HTML实际内嵌数据。二者均不重新分析、不连接数据库或模型；已有成品无需每次演示都重建。构建检查消费CSV自身哈希及样本、比值、节点和参照关系；6条历史父manifest指纹漂移警告保留在[source_manifest](../WEB/source_manifest.json)中，不宣称全部历史链同步通过。

## 5. 任务3：完整过程与可配置分组

当前WEB提供“每组款数/组数均分”控件，默认按每组2款；界面一次只启用一种分组方式，减少两个参数冲突。

- 指定每组款数K：顺序切分，末组保留余数；5款K=2为2＋2＋1，K=3为3＋2。
- 仅指定组数G：尽量均分，前面组多1款；5款G=2为3＋2，不能出现空组，单组仍最多5款。
- 原Python兼容调用若同时传两参数，实际组数须一致；WEB只启用一种分组方式，不会同时传入两种要求。

当前每组一个完整节点曲线叠加区，保留游戏颜色，用粗线标最大相邻相对降幅，下方逐游戏给出该区间说明。图09的逐区间柱图保留原图入口，尚未做成所选游戏的独立交互柱图。后续扩展时应按游戏分别展示相邻区间，不能把不同游戏的区间强行按同一章节并列。

当前曲线悬浮包含成就展示名、序列位置、原始覆盖、相对首覆盖、原剧情数组下标和已有描述；首/中/末原文另在阶段卡查看。横轴明确标“节点相对位置，非时间”。后续若增加相邻区间专用控件，再展示两端成就及覆盖、相邻推进比、相对降幅、百分点差和并列标记，数据可复用已存adjacent结果。

手动选择不受自动案例的同类型、六节点或全程相近条件限制。两节点游戏只显示首末及一个区间，提示没有内部过程。当前WEB开场固定展示一对实际过程案例，后续探索区使用全局选择；原Python自动案例报告和图仍通过附件查看，避免把自动挑选的极端差异案例说成任意游戏的代表。

已有可复用函数在[compare_trajectory.py](../analysis/T1Core/compare_trajectory.py)：

```python
# 从T1Core模块目录调用；网页封装需配置正确的模块导入路径。
from compare_trajectory import query_trajectory

data = query_trajectory(
    [367520, "机械迷城"],
    kind="mixed",
    games_per_group=2,
    group_count=None,
)
```

它只读返回selection和groups，每款含appid/name_en/name_zh、profile、nodes、adjacent，不画图、不写文件。它仍依赖默认底表、manifest和借用SQLite名称/指纹校验；不是可直接搬入Go进程的HTTP处理器。已有的分组data.json也只包含该次所选游戏，不是完整198款的统一网页发布包。

### 6.2 高亮具体做什么

1. 加载固定65款数据集，按appid建立索引。这65款是统计背景，不随搜索或选择缩小。
2. 读取全局selected_appids，与65款AppID取交集得到可高亮集合；其他选择保留在芯片/卡片中并显示不可用原因。
3. 背景点保持现有数据编码；给选中点增加较大描边、外环或形状标记，并在附近显示名称。选中多款时，外环与右侧卡片使用稳定的选择颜色。
4. 保留原填充色含义：图10填充色仍表示全程推进；13～15原来的R<1/R>=1图例仍有效。不要把选中颜色直接替换全部原编码而使色条/图例失效。
5. 右侧卡片始终对应当前选中的游戏，不再受原静态图右侧极端案例名单限制。可保留另一个“预置案例”折叠区，明确与用户选择不同。
6. 鼠标悬浮可以临时强调一个点；点击点可加入全局选择，达到5款后提示容量。清空选择只清高亮和卡片，总体65款背景仍在。

如果图表组件用单独的高亮图层覆盖原点，逻辑数据集仍只计65个唯一AppID；统计与悬浮信息按AppID去重，不把覆盖点当成新增观测。重合点使用候选提示或卡片定位，不修改真实坐标来区分；当前分析没有给RAWG整数小时加统计抖动。

### 6.6 信息卡与悬浮信息

建议每款卡片显示：显示名＋AppID、平均游玩时长、三类HLTB耗时、当前选择的时长比、首/中/末覆盖、前/后/全程推进、节点数及统一/多结局代理标记。篇幅不足时默认显示平均时长、当前参照、R和全程比，其余折叠。

散点悬浮至少给出名称/AppID、当前横纵轴原始数值、参照字段含义和单位。图13～15额外显示RAWG与当前HLTB原值，例如“7h / 41.37h = 0.169倍”。比值不能显示为“完成16.9%支线”；较小的R显示三位或更多有效小数，避免0.002被显示成0.00。

### 6.7 不在65款中的选择怎么处理

## 10. 查询接口建议：与已实现函数区分

当前WEB直接筛选HTML内嵌的冻结数据，无需这些路由。若未来由后端提供数据，下表仅为建议的只读GET契约，当前仓库没有下列分析路由，不能当作已上线API调用：

| 建议接口 | 作用 |
|---|---|
| GET /api/lyx/t1/games?q=… | 搜索198款，返回名称、AppID与各视图能力；由选择器消除名称歧义 |
| GET /api/lyx/t1/overview?topic=types或time | 返回固定总体数据、统计、范围与版本 |
| GET /api/lyx/t1/compare?appids=367520,40700&view=stages | 按输入顺序返回所选指标，最多5款 |
| GET /api/lyx/t1/compare?appids=367520,40700&view=trajectory&games_per_group=2 | 返回所选分组节点/区间，可映射已有query_trajectory逻辑 |
| GET /api/lyx/t1/compare?appids=367520,1593500&view=time&reference=extra | 返回可定位所选信息、缺失原因及统计版本；固定总体仍为65款 |
| GET /api/lyx/t2/reputation?view=stages&appids=367520,1593500 | 固定183款背景/对应统计和选择状态；view=sources则固定共同140款 |
| GET /api/lyx/t2/peers?config=main&appids=367520,397950 | 当前条件背景/覆盖与所选目标统计/参照；config切换由发布数据适配实现 |

名称在搜索环节解析，业务查询统一发送AppID，仍满足AppID/name_en/name_zh三种输入需求。以上路由只是建议，当前Python函数不是现成HTTP接口；任务6已有网页离线config索引可复用，但还没有对应HTTP处理器，见8.5。后端若实现，需验证范围、重复、1～5款限制及任务3分组参数。任务3若开放高级多组，应显式说明容量，不让任务1接口悄悄接受更多游戏。

建议的时长响应字段示意如下，属于待封装契约，不是已存在的函数返回值：

  "selected_appids": [367520, 1593500],
  "highlighted_appids": [367520],

总体65个点及统计可通过一次overview加载缓存；选择响应不必重复传全量。缓存按数据版本、视图、参照和有序AppID区分；旧版本统计不能与新版本逐游戏值混用。当前Python查询需要原快照校验，若走离线发布包方案，应在构建阶段完成校验并在网页保留版本说明。任务5默认结果刷新后，任务6须重新生成以匹配上游manifest；发布时原子替换完整同版本文件组，避免新口碑与旧参照混用。

## 11. 页面验收的关键场景
