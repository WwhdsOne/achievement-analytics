游戏目录以本专题的198款为范围，字段至少包含appid、name_en、name_zh、主类型，以及三节点、65款时长、共同140评分、参照可用性的能力标记。已导出的game_catalog.csv提供198款名称索引；能力需按同AppID连接资格台账/结果，不把名称目录误当作完整能力表。全站若已有1000款搜索，需要明确“本专题可分析198款”，范围外结果显示不可用原因，不自动加入分析。

建议常规网页最多选择5款，保持用户选择顺序；同一AppID只能选一次。任务3的Python入口支持跨组更多游戏，可作为高级入口，但单组最多5款。任务1、5、6实际总数仍最多5款，不能把任务3的容量直接套过去。

搜索结果显示名称和AppID，选中后统一存selected_appids。可以按AppID、name_en、name_zh查询；名称歧义时展示候选，不能任选一款。当前198款name_zh均非空，但只有51条含汉字，部分字段仍为英文；不保证任意中文译名均可命中。显示名优先用已有name_zh，否则name_en，不生成翻译。

初始没有选择时，类型、时长和口碑页显示总体图，同类参照页显示181款背景及明确标识的自动案例；指标页可显示明确标为“示例”的既有五款，或提示选择游戏；过程页可展示既有自动案例。不要把空选择误当成用户已经选择CLI的默认五款。

## 5. 任务3：完整过程与可配置分组

控件建议为“分组方式：按每组款数/按组数”。默认按每组2款；界面一次只启用一种分组方式，减少两个参数冲突。

- 指定每组款数K：顺序切分，末组保留余数；5款K=2为2＋2＋1，K=3为3＋2。
- 仅指定组数G：尽量均分，前面组多1款；5款G=2为3＋2，不能出现空组，单组仍最多5款。
- 兼容调用若同时传两参数，实际组数须一致；错误时解释原因，不删除最后一款凑容量。

每组一个展示区：上方叠加完整节点曲线，下方按游戏分别展示相邻区间。不同游戏的区间柱不能强行按同一章节并列；横轴是各自节点序号。建议选中游戏在组内保持颜色，最大相对差距另用线宽/标记编码。

曲线悬浮包含完整成就展示名、序列位置、原始覆盖、相对首覆盖、stage、是否首/中/代表结局；相邻区间悬浮包含前后成就名、两端覆盖、相邻推进比、相对降幅、百分点差及是否最大/并列。归一横轴明确标“节点相对位置，非时间”。

手动选择不受自动案例的同类型、六节点或全程相近条件限制。两节点游戏只显示首末及一个区间，提示没有内部过程。默认自动案例作为独立模式保留，避免把自动挑选的极端差异案例说成任意游戏的代表。

已有可复用函数在[compare_trajectory.py](../analysis/T1Core/compare_trajectory.py)：

```python
# 从T1Core模块目录调用；网页封装需配置正确的模块导入路径。
from compare_trajectory import query_trajectory

data = query_trajectory(
    [367520, "机械迷城"],
    kind="mixed",
    games_per_group=2,
    group_count=None,
)
```

它只读返回selection和groups，每款含appid/name_en/name_zh、profile、nodes、adjacent，不画图、不写文件。它仍依赖默认底表、manifest和借用SQLite名称/指纹校验；不是可直接搬入Go进程的HTTP处理器。已有的分组data.json也只包含该次所选游戏，不是完整198款的统一网页发布包。

### 6.1 布局与三个子视图

建议时长页的主图占左侧约三分之二，右侧放所选游戏信息卡，下方放选择对比表与解释。顶部说明“固定65款；当前选中N款，其中M款可定位”。常规选择上限5款，不把M误显示为统计样本数。

|---|---|---|
| 两类时长对照 | 10 | x=main_hours，y=playtime，颜色=全程推进，y=x参考线 |
| 时长与阶段推进 | 11～12 | x选择main_hours或playtime；y选择前段、后段、全程，或同时保留三个面板 |
| 相对参考投入 | 13～15 | 参考耗时选择主线/主线＋支线/全收集；x为对应时长比，y固定全程推进 |

图10先保留现有主线参照口径，避免切换分母后还沿用原相关系数。图11～12可用已保存的六项时长—阶段关联；图14～15目前只计算与全程推进的关联，不把“前/后段”控件扩展到这些口径并借用其他统计值。

### 6.2 高亮具体做什么

1. 加载固定65款数据集，按appid建立索引。这65款是统计背景，不随搜索或选择缩小。
2. 读取全局selected_appids，与65款AppID取交集得到可高亮集合；其他选择保留在芯片/卡片中并显示不可用原因。
3. 背景点保持现有数据编码；给选中点增加较大描边、外环或形状标记，并在附近显示名称。选中多款时，外环与右侧卡片使用稳定的选择颜色。
4. 保留原填充色含义：图10填充色仍表示全程推进；13～15原来的R<1/R>=1图例仍有效。不要把选中颜色直接替换全部原编码而使色条/图例失效。
5. 右侧卡片始终对应当前选中的游戏，不再受原静态图右侧极端案例名单限制。可保留另一个“预置案例”折叠区，明确与用户选择不同。
6. 鼠标悬浮可以临时强调一个点；点击点可加入全局选择，达到5款后提示容量。清空选择只清高亮和卡片，总体65款背景仍在。

如果图表组件用单独的高亮图层覆盖原点，逻辑数据集仍只计65个唯一AppID；统计与悬浮信息按AppID去重，不把覆盖点当成新增观测。重合点使用候选提示或卡片定位，不修改真实坐标来区分；当前分析没有给RAWG整数小时加统计抖动。

### 6.3 选中后哪些东西必须保持不变

| 内容 | 是否随选择变化 |
|---|---|
| 固定背景65款、它们的坐标和指标 | 不变；切换视图/参照才按该视图更新坐标 |
| 总体样本数n=65 | 不变 |
| 当前视图的总体Spearman和95%重采样区间 | 不变，读取对应预计算结果 |
| 13～15的全程推进比中位数参考线 | 不变，来自同65款；约34.22% |
| 时长相等线y=x、时长比参考线R=1 | 定义不变，不是通关阈值 |
| 当前视图的坐标范围与色阶 | 在同一视图内固定，不因只选一款自动缩放 |
| 点的高亮、名称标注、右侧卡片、选择对比表 | 随选择更新 |

不要在选了两款后把标题改成“n=2总体时长分析”，不要用两款重新计算Spearman、Bootstrap或中位数横线。这里的交互是在既有研究背景中定位游戏，不是开展一个新的小样本统计实验。

### 6.4 切换参考耗时如何更新

建议内部reference取main、extra、completionist，映射如下。不要从显示中文字符串推断字段。

| reference | HLTB原值字段 | 横轴比值字段 | 总体相关结果 |
|---|---|---|---|
| main | main_hours | time_ratio | time_correlations中x=time_ratio、y=overall_progress_ratio |
| extra | extra_hours | extra_hours_ratio | reference_correlations中reference_field=extra_hours |
| completionist | completionist_hours | completionist_hours_ratio | reference_correlations中reference_field=completionist_hours |

切换时同时更新65款背景的横坐标、选中点横坐标、x轴标题、参照口径说明、总体相关系数/区间及卡片当前R值；所选AppID列表和各游戏纵坐标p_f/p_s保持不变。各参照的x轴范围按全65款预先确定，切回同一参照应恢复相同范围。

Main + Extras显示“主线＋支线/额外内容”，Completionist显示“全收集参考耗时”，说明后者不等于Steam全成就。纵轴仍为主线推进，不能切换分母后把图名改成支线参与率或全收集完成率。

### 6.5 一个真实例子：Hollow Knight

AppID=367520在65款中。数据来自reference_cohort：

| 项目 | 本次值 |
|---|---:|
| RAWG平均游玩时长 | 7小时 |
| HLTB主线/主线＋支线/全收集 | 26.94 / 41.37 / 62.37小时 |
| 首节点/代表结局覆盖 | 71.3% / 24.4% |

选择该游戏后，图13～15上的高亮坐标依次约为(0.260,34.22%)、(0.169,34.22%)、(0.112,34.22%)。换参照只水平移动；纵轴不是代表结局原始覆盖24.4%。三种比值都保存在数据中，无需网页请求模型或重新计算分析任务。

### 6.6 信息卡与悬浮信息

建议每款卡片显示：显示名＋AppID、平均游玩时长、三类HLTB耗时、当前选择的时长比、首/中/末覆盖、前/后/全程推进、节点数及统一/多结局代理标记。篇幅不足时默认显示平均时长、当前参照、R和全程比，其余折叠。

散点悬浮至少给出名称/AppID、当前横纵轴原始数值、参照字段含义和单位。图13～15额外显示RAWG与当前HLTB原值，例如“7h / 41.37h = 0.169倍”。比值不能显示为“完成16.9%支线”；较小的R显示三位或更多有效小数，避免0.002被显示成0.00。

右侧下方的1～5款对比表可并列三类耗时比，帮助看见同一游戏随分母变化的位置。该表是所选游戏详情，不另计算小样本总体相关；如果以后新增时长分组柱图，应明确属于新增展示，不冒称当前已有对应的CLI图号。

### 6.7 不在65款中的选择怎么处理

示例：God of War，AppID=1593500，在198款主线范围中，但RAWG时长缺失。筛选记录中main_hours=20.55、rawg_status=null、exclusion_reason=rawg_null，因此不进入当前65款时长样本。

页面应保留它的选择芯片：任务1、3正常展示；时长页卡片提示“RAWG平均游玩时长缺失，未进入固定65款时长分析”，可显示发布包中已有的20.55小时主线参考值，但不绘制假点，不把平均时长或R补0，也不在选择时临时追加到总体样本。

如果5款里只有3款可定位，显示“已选5款，时长图可定位3款”，背景仍n=65。若0款可定位，保留总体图和各条缺失说明，允许用户继续换选；不要显示空白分析图或清空其他页的选择。

现有duration_eligibility对198款保留hltb_status、rawg_status及主要排除原因；若将代码值翻译给用户，区分本地未匹配、NULL、零值、缺三节点等情况。“本地未匹配”不能写成“HLTB网站没有该游戏”。

## 7. 任务5：固定口碑背景、评分切换与探索详情

### 7.1 页面布局与三个视图

建议延续时长页“主图左侧＋所选卡片右侧＋解释/明细下方”的结构，顶部固定版本与三节点资格。三个视图分别对应图16四象限、图17阶段关联、图18评分来源对照。每次切换同时更新标题、样本说明、评分单位、统计键和缺失提示，不能只替换横坐标而沿用旧系数。

| 视图 | 背景 | 横纵轴与辅助信息 |
|---|---:|---|
| Steam与全程 | 183款 | x=steam_positive_ratio，y=overall_progress_ratio；中位四象限、固定区域色、预置案例 |
| Steam与阶段 | 同183款 | x=Steam好评率，y=前/后/全程三阶段；每面板读取对应Spearman与区间 |
| 三评分对照 | 共同140款 | Steam/Metacritic/RAWG保留各自单位，对照同三阶段；注明共同人群与成对系数差 |

Steam比例0～1显示百分比，Metacritic为0～100，RAWG rating为0～5。坐标和悬浮保留来源单位，不把媒体85分换成85%后与RAWG85%作未经定义的综合分。图18坚持同140款，不能各评分用各自全有效样本。

### 7.2 所选游戏如何定位

沿用全局selected_appids最多5款。图16/17以183款索引，图18以共同140款索引；选中描边/标签与详情卡关联，保留四象限原填充色。总体点、分界、中位线、相关系数、区间和坐标范围不因选中一款而改变。

| selected.selection_status | 图面行为 | 卡片说明 |
|---|---|---|
| available_all_panels | 三类视图均可高亮 | 展示完整评分与阶段值 |
