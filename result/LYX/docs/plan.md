# LYX总体规划：DeepSeek LLM as Judge成就分类

更新：2026-10-15。负责人刘宇翔。当前交付：**按游戏名或AppID定位本地数据，复用或生成背景摘要，一次性分类整款成就；有效结果累计到CSV，达到门槛的标签保存到SQLite。工程链路已实现并有真实运行证据，冻结1000款的分类尚未全部完成。**

这里的 **LLM as Judge** 指DeepSeek按固定八类定义对成就原文作语义判别，不是新增另一个模型评审器。游戏背景、类别规则和整款原文构成判断上下文；模型返回标签、自报置信度、原文依据和理由，程序负责契约校验与入库筛选。响应结构正确、置信度达到门槛均不等于语义已获人工确认。目前没有人工金标集、准确率或主线节点质量的统计结论。

主线漏斗、参与深度等是分类数据的后续用途；主线节点人工核验、剧情排序与聚合分析尚未实施，本轮不扩展为强制人工审核程序或规则模型比较。自动`mainline`只表示类别候选，不能证明必经性、先后关系或普通玩家通关率。

编辑、代码和产物只在result/LYX，其他目录只读，远端PostgreSQL永远只读；修改前同步main，不自动提交/推送。说明与实验集中在docs。

## 阶段一：固定原始输入（已完成）

前1000款按远端store_search_games.review_count DESC、appid ASC冻结；已有1000款、71,465项成就，996款有成就。四张背景表和成就已迁入本地六表。保留描述缺失、两款FF7源冲突及版本映射疑点，不伪造条件；日常分类不连接远端、不抓网站。

本地没有游戏简介字段，不新增简介列。标签表已增加display_name并按(appid,api_name)回填，方便直接查看分类；当前六表、schema版本4，原始成就可追溯，模型派生摘要在外部缓存与报告记录。

## 阶段二：游戏定位与背景摘要（已实现并真实执行，语义效果待评估）

--game-name匹配本地name_en/name_zh，唯一完整匹配才得到AppID；部分、相似或重名只展示候选。保留AppID/清单/全库选择，默认前1000款。

游戏选择参数四选一：--game-name单款完整名称、--appids一款/多款正整数、--appids-file纯AppID数组JSON、--all-games本地全部游戏。不写选择参数使用冻结前1000款，无子命令默认plan；详细命令与默认值见[PROCESS.md](PROCESS.md#游戏选择参数)。

新增process/game_intro.py，导入区之后为GAME_INTRO_PROMPT常量。根据中英文名和官方类型生成40～80字符摘要，无法识别则返回空摘要和原因。源标记model_generated，不能作为官方资料或成就条件证据；不产生章节、等级上限、DLC条件等细节。

简介使用独立版本及缓存命名空间，成功生成后复用；复用DataAgent客户端和同一请求预算，不各自超发。源输入、模型或简介版本改变会改变缓存指纹。HTTP 200但格式不合规时只将本款记为response_error，总时限或读超时记request_timeout，均跳过本款且不请求分类；同类连续超时触发暂停，其他网络等整体错误仍停止。recognized=false仍可继续按成就文本分类。

## 阶段三：固定分类规则与整款输入（已实现）

DataAgent.py导入区之后为CLASSIFICATION_PROMPT常量，包含八类定义、多标签/未知互斥、边界示例、背景使用和输出契约。普通成长不能仅因数字门槛归挑战。

| type | 定义 |
|---|---|
| mainline | 主线推进或结局，不证明顺序/必经性 |
| side | 可选支线任务/剧情 |
| collection | 收集、探索或集合完成 |
| challenge | 明确特殊难度、技术、成绩或限制条件 |
| multiplayer | 条件必须多人、在线或合作 |
| dlc | 条件依赖扩展内容 |
| other | 明确但不属于上述，包括普通成长/操作或全成就汇总 |
| unknown | 证据不足，必须独占 |

输入排列为固定system → game_context名称、类型、模型摘要及来源/疑点 → achievement_batch全部原始成就。短引用id关联回本地身份，不传完成率、评分、时长、旧标签或来源排序。原始条件优先，依赖模型背景时声明知识使用与疑点。

取消正常入口的固定数量批次与sample-size，默认一款一个分类请求，缓存可免新请求。当前分类prompt版本v6，简介v1；evidence为每项1～2段非空的对应成就原文，每段严格小于500字符（最多499，含空格标点），reason/uncertainty各最多40字符。evidence是原始文字依据，reason是分类解释，两者都不能单独证明语义正确。完整响应逐项校验闭集、多标签、互斥、置信度、原文依据和完整ID覆盖；错误仍拒绝本款写库，记录后继续下一款。主线类别不触发排序或分析任务。

## 阶段四：预算、保护与可恢复存储（已实现）

先plan预检。输出估计1024+160*N，默认上限65536，输入字符阈值300000；超限单列oversized_game，不自动拆分。输入字符数不是token，输出估计不是实际用量保证；少数大型游戏后续再显式调整预算或另行批准拆分。

首次普通游戏通常为简介1次+分类1次，不含重试，缓存简介后通常只需分类；默认max-requests=2含两阶段、失败尝试和重试，每轮重新计数，缓存不计。0仅允许缓存，20次冷缓存预算通常约10款；选择全量不意味着预算不限。每轮classify先备份，完整响应先持久化再写库，支持简介完成后的预算暂停和完整响应完成后的中断恢复。v6优先读当前缓存，仅当长度规则和版本不同、其余完整输入/摘要/模型/接口/生成参数完全一致时兼容v5/v4响应，并按严格len<500及其他全部规则重校验。旧receipt不改写，新响应使用新时间戳文件，运行报告也独立落盘；可用--max-requests 0尝试恢复已有完整响应。

HTTP传输由process/deepseek_transport.py处理可取消的异步等待，业务仍逐款串行、stream=False，分类prompt v6/简介v1与输入指纹不变。--timeout-seconds默认300秒仍是读超时，连接上限15秒；另增简介总时限--intro-total-timeout-seconds=90、分类总时限--classification-total-timeout-seconds=300。从首次网络尝试到完整正文共用总时限，有限重试/退避包含在内，保活空行不延长。每15秒输出游戏/任务、请求数、阶段、累计/剩余时间、接收字节、非空白正文及最后接收时间，并更新本轮progress.json；无数据也更新，不将少量数据视为完整结果。

总时限到达或读超时后取消本地等待，关闭响应、记request_timeout，本款不写库且不自动重发同一请求。简介失败不分类，分类失败保留已成功简介。完整正文为response_text；未完成正文为partial_response_text、response_complete=false，仅留档、不复用或入库；旧receipt缺少该字段按历史完整规则兼容，显式false禁止复用。已发生的尝试仍计预算，服务端是否已处理及无usage时费用均未知，不记成零消耗。

整款模型可见全部原文，默认只更新待处理项，已有DeepSeek/uncertain保留；--reclassify重判机器结果。人工approved/manual和非空排序号始终保护。写入前核对完整成就集合及文本，新增/删除/变化回滚；短事务更新标签（同步展示名）及suggested/uncertain，不动原始字段，日常分类不自动迁移结构。

非保护成就的status为suggested/uncertain且全部标签method=deepseek才记完成；已有rule/jev标签不能跳过。整款pending_count=0即跳过简介/分类请求；仍读取本地数据库判断进度。部分未完成时仍用整款原文和缓存，--reclassify也不强制发新API请求。

逐标签入库门槛默认0.6，confidence >= 0.6通过，多标签独立筛选；仅低于门槛的标签留档而不写入SQLite。confidence是模型自报判断信心，不是校准后的准确概率。types保留原始完整结果，accepted_types/rejected_types列出筛选结果；report记录confidence_comparison=">="。全部未通过时保留旧标签和status，计入未完成；unknown通过门槛后仍uncertain，明确类别为suggested。门槛和比较符属于本地后处理，分类prompt仍为v6、API请求指纹不变；更改门槛可复用相同完整输入的缓存，普通分类已有机器结果重筛需--reclassify，不自动清理历史数据。

新增process/datacache.csv累计有效分类，每标签一行，包含未通过门槛、已有、受保护及本轮写入结果。每款完整校验后先累计留档，再提交SQLite，提交后刷新写入结果；按(appid,api_name,type,request_hash)去重，source_csv/first_seen_at/last_seen_at保留追溯，原runtime CSV/JSON与报告继续保留。普通分类命令不变，可用--datacache指定LYX内路径。

| 保存层 | 作用 | 不能据此认定的事项 |
|---|---|---|
| 请求receipt与响应缓存 | 保存请求身份、完整原始响应、错误或部分正文；相同输入可重校验复用完整响应 | 部分正文不能作为有效缓存；HTTP 200不保证响应契约或分类语义正确 |
| 每轮report.json / classifications.csv | 固定本轮参数、游戏状态、请求/用量与各成就标签结果，逐轮独立保留 | 缓存命中的候选也会导出，行数不等于本轮新增入库量 |
| process/datacache.csv | 跨轮累计有效标签，保留低分、已有、受保护及写入结果与来源 | 是审查/追溯台账，不参与自动跳过判定，也不是另一套模型响应缓存 |
| 本地SQLite | 保存通过门槛、满足保护和上下文校验的实际标签及成就状态 | 分类入库不等于人工审核通过；低分仅在文件留档不会变成已完成 |

部分游戏仍有低分成就时，下次普通分类仍视其为待处理，并可能重放整款缓存：已入库标签跳过，低分继续留档；这不会额外消耗API预算，也不会因再次留档自然提高置信度。`--max-requests`只限制新HTTP尝试，缓存命中不计数、失败和重试计数；因此“处理了多款缓存游戏但终端只显示另一款的新请求”是正常顺序。精确指纹避免跨游戏混用；累计CSV也不能用来替代指纹和完整响应校验。

历史缓存通过process/import_classification_cache.py离线迁移：默认plan预检，--apply才实际写入，实际库先备份。默认扫描runtime/deepseek/runs，支持--source-root/--database/--datacache/--min-confidence；核对当前成就文本及关联完整响应后，将有效记录累计到CSV、按>=0.6只补缺失标签，已有机器/人工结果和主线排序保留。旧上下文、坏CSV或证据无效项拒绝导入并报告，不连接远端或调用DeepSeek。迁移与后续普通任务共用相同门槛和结果解释，数据量与实际验收另记experiments.md。

分别统计本地响应复用、API命中/未命中token、两阶段用量、剩余工作及失败。HTTP 200中的无效JSON、截断和简介/分类契约错误按游戏隔离，记response_error及阶段；总时限/读超时记request_timeout，两类均不写本款且继续后续游戏。简介和分类各自累计连续超时，同类真实请求收到完整HTTP 200响应清零，缓存不清零；同类连续3次超时整轮service_paused、退出码1。报告failed_game_count/failed_appids包含两类失败，timeout_game_count/timeout_appids单列超时，consecutive_timeouts及paused_reason记录暂停原因。遍历结束有零星失败则completed_with_errors、退出码1；预算先耗尽仍budget_reached且保留此前失败。429、TLS/认证/余额、非读超时网络故障、SQLite及文件错误仍停止，连接错误/5xx仅有限退避并共享总时限。没有数据/超规模/预算耗尽/暂停/错误各自明确，不把请求失败当unknown；此前已提交结果保留。Ctrl+C仍正常收尾为interrupted，本次不建立额外停止命令或停止标记。

2026-10-15北京时间11:06的离线补录快照：扫描9份历史CSV共2666标签行，去除重复回放后datacache累计2264行，其中107行低于0.6；实际补录74个`confidence=0.6`标签，涉及68个原未分类成就及6个已有成就的缺失标签。1条不相容新候选标记`conflict`，保留数据库旧结果；已有机器标签、人工结果和主线排序不覆盖。补录没有调用DeepSeek或远端数据库，重复导入新增0标签。以上是一次历史迁移，不是1000款全量完成报告。

同日14:41的后续真实分类运行在2次新请求预算内新增49条标签、复用5次本地响应，最终`budget_reached`；累计CSV增至2313行，低分仍107行。后续数据会继续变化，使用最新离线`plan`和带时间运行报告核对覆盖，不把这里的固定快照当实时进度。成就数、标签行数、实际写入量和完整游戏数分别统计；`successful_game_count`只表明该款处理完成，可以含低分拒绝，不能代替整款已全部分类。

完成标准：待处理成就有通过入库门槛的标签或明确未完成记录，原始字段与受保护结果不变；分类覆盖率和语义准确率分别解释。预算耗尽、service_paused、completed_with_errors、success_with_skips或success_with_rejections不能称全量完成。长度边界、`0.59/0.6/0.61`筛选、旧缓存恢复、失败后继续、持续空行的硬总时限、无数据心跳、连续超时暂停、完整/部分响应隔离及重复导入均有独立验证记录；离线传输验证不证明真实API持续可用，结构校验也不证明分类正确。

继续推进的顺序：先离线预检和缓存恢复，再按显式预算处理可运行游戏；对服务忙/超时、契约错误、超规模、描述缺失和低分分别保留工作清单。分类覆盖推进后再组织人工分层抽查，优先核对`mainline`、模型背景知识参与判断和缺失描述项；建立人工基准后才能报告准确率或讨论规则效果。主线章节/结局节点的必经性及剧情顺序需另行核验，完成后才开展漏斗和标签相关的聚合分析，不能直接把自动分类当粘性或因果结论。

交付代码、schema说明和实验记录；缓存、原始数据和备份Git忽略，冻结选样的top1000_appids.json与top1000_selection.json已按用户要求保留Git跟踪例外。后续质量抽查不等于已实现强制人工审核程序；摘要和整款调用是否提高质量、API前缀缓存是否降低费用，仍需另有可比数据支持。本次文档同步未发模型请求或写数据库。
