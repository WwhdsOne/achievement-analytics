# YJH 标签口径审查

审查日期：2026-10-16。范围：当前工作区的 `tag_trends.py`、`experiments.md`、入库逻辑与 schema；未重新查云库、未重跑统计。脚本已有本地未提交修改，本次未改动它。

## 结论

**SteamSpy tags 作为数据来源合适；研究“游戏类型演变”时，建议以其中的 genre / subgenre 为主，feature、theme、画风等分别分析。无需把整个数据源换成粗粒度的官方 genre。**

最容易误解的是：当前 `kind='theme'` 并不表示 Steam 官方语义分类中的“题材”。`cleaning/writers.py:471–483` 对 SteamSpy 返回的每一个 tag 都统一写入 `kind='theme'`。因此 YJH 的筛选实际上取得的是混合维度的 SteamSpy 标签，而不是只取得科幻、奇幻等题材。

`kind` 是本项目的入库标记，与分析层面的 genre / feature / theme 是两套分类。不能直接把 SQL 改成 `kind='genre'` 或 `kind='feature'`：当前 schema 只允许 `theme`、`platform`，也没有按这些语义分类存储 SteamSpy 标签。

## 应该用哪个维度

| 要回答的问题 | 建议主维度 | 示例与来源 |
|---|---|---|
| 各发售年份的游戏类型结构如何变化 | Genre / subgenre | 从 SteamSpy tags 中筛选 RPG、FPS、平台游戏、类银河战士恶魔城等 |
| 哪些机制或玩法特色更常见 | Feature / mechanics | 程序生成、资源管理等；单独统计 |
| 哪些题材设定更常见 | Theme | 科幻、奇幻、中世纪等；单独统计 |
| 画风、视角如何变化 | Visuals / viewpoint | 像素画风、2D、第一人称等；单独统计 |
| 单人、多人、合作和支持功能如何变化 | Players / support | 标签可描述定位；实际支持情况优先用 `steam_appdetails.valve_categories`，并核对字段覆盖率 |
| 需要简单、易解释的类型对照 | 官方 genre | 用已有 `steam_appdetails.valve_genres` 做粗粒度对照；先报告覆盖率，不默认它优于细分标签 |

Steam 官方标签文档明确将类型、视觉、主题、特色与玩家支持分开，类型还区分主类型、类型和子类型。按这些维度组织分析有官方依据；具体映射仍需记录规则和版本。[Steam 标签文档](https://partner.steamgames.com/doc/store/tags?l=schinese)

## 发现与影响

1. **主结果混合多个维度，不宜整体称为“类型增长排名”。** `tag_trends.py:666–707` 对全部标签排序；实验记录中的领先项包括 Colorful、Cute、Pixel Graphics，以及全窗口中的 Singleplayer、Controller。它们可以作为标签趋势结果，但不能统一解释成 genre 趋势。建议主榜只比较类型与子类型，其余维度各出一张补充图。

2. **人工分类存在明显混放与漏项。** `tag_trends.py:124–160` 将 Indie、Procedural Generation、Level Editor、Character Customization、Moddable 等都放进“玩法类型”；Exploration 未进入映射，按 `:323–326` 会落到“其他”。建议把制作属性、机制、编辑与模组支持移出类型，并输出未分类标签清单。某些标签有交叉语义，应说明采用的归类规则。

3. **“至少有一个玩法标签”的类目占比信息量很低。** 当前类目统计是游戏是否命中该类任一标签（`:328–332`），实验记录显示“玩法类型”接近 100%。这不能区分 RPG、策略或射击的结构变化；隐藏这条线改善了图面，但主分析仍应比较具体类型/子类型的占比。

4. **更换分类无法消除年度可比性问题。** 现有记录已报告 2024 年标签覆盖率为 82.3%，2025 年为 34.4%，且缺失与免费游戏相关；平均标签数也有明显变化。保留覆盖率、标签密度和仅付费样本对照是合理的。不过“只看付费游戏方向一致”只能说明对该样本限制较稳健，不能证明已排除所有缺失偏差。以上数值来自既有实验记录，本次未独立复算。

5. **“非游戏条目排除”尚未落实为样本排除。** `:323–332` 只是把命中 `EXCLUDED` 的标签标为“非游戏条目”；此前的标签占比和分母已经计算，也没有据此删除 appid。若实际样本包含软件或影片，它们仍可能进入统计。应先核验应用类型，再确定统一的游戏样本；不能仅凭某个标签删除整款游戏。

## 建议执行顺序

保留现有 SteamSpy 原始标签及数据表，在 YJH 分析层维护一份带版本的语义映射；主结果分析具体 genre / subgenre，feature、题材、画风、玩家模式分组呈现，免费与抢先体验等商业/发行属性另列。不同维度共用固定样本，同时报告各自标签覆盖率，避免更换分母后误比。

先用现有官方 genre 做简单对照，再评估细分标签是否带来更有解释力的结果。不要把全部 tag 的票数当作玩家偏好强度：标签描述游戏属性，不等于“玩家更愿意玩”。当前分析支持的结论是**抓取时标签所描述的不同发售年份游戏结构**；发行占比上升不能直接证明历史热度或玩家偏好上升。
