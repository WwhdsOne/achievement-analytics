# 游戏寻迹：面向玩家的发现页设计

日期：2026-10-15。用户已选择 A「游戏发现」并明确确认具体方案；本文件是已实现的改版规格。真实页面在独立交付目录完成，本轮验证与证据边界见文末。

## 目标与范围

让普通玩家完成「选择喜欢的游戏 → 浏览下一款游戏 → 了解为什么推荐 → 打开 Steam 详情」。默认界面突出游戏与推荐理由，保留可解释推荐专题的完整关系、贡献与来源。

本轮工作对象为 `交付版-单服务入口/result/ZZY/` 当前交付源码。实施时创建独立的新交付目录，保留 v5 ZIP 及原目录，以便对比和回退；验证后生成新版本包及摘要。不移动或覆盖 System32 原项目，不提交或推送，不写共享数据库，不改变推荐方法、候选资格、联合权重或年份计算方式。

## 已比较的方向

- A 游戏发现：深色界面、游戏封面与推荐卡片优先，解释按需展开。用户已选择。
- B 极简工具：更紧凑、搜索效率高，但游戏氛围较弱。
- C 图谱探索：关系展示突出，阅读负担较重，更适合技术探索。

草图为 `.superpowers/brainstorm/20261015-user-discovery/content/discovery-v1.html`。其中固定示例卡片、手写理由和限定搜索不进入正式版；正式页面全部使用实际接口返回。

## 页面与交互

1. 导航使用「发现游戏」「推荐依据」，辅助入口收进「了解推荐」。首页不并排陈列四个技术工具。
2. 首屏标题为「从喜欢的游戏，找到下一款」。搜索提示支持中文名、英文名和现有别名。保留搜索分页及资格说明，最多选择 3 款；已选项可以移除、替换。
3. 主按钮为「发现下一款游戏」。未选择游戏时禁用。年份放在「筛选」中，可输入起止年份并清空，含义与已有服务一致。默认推荐 5 款，保留现有 1/3/5 数量选择但放在筛选中。
4. 查询期间展示加载状态并防重复操作。选择或筛选变化后清除旧结果或标明需要重新推荐；取消、清空、重试与已有异步过期响应保护继续有效。
5. 桌面结果采用三列卡片，手机单列。卡片显示真实游戏名称、封面、实际发售年份、最多 3 个有依据的匹配标签、一句简短理由，以及「为什么推荐」「Steam 详情」。不显示 appid、八位小数分数、IDF 参考库或算法版本。
6. 「为什么推荐」展开当前卡片的真实详情：首先是匹配关系与所选游戏的联系，其次为关系图及来源。完整贡献表、原始证据和查询报告在「详细依据」中折叠保留。用户可以辨别仅共享事实与确实参与评分的关系。
7. 页面底部保留简短说明「根据游戏关系寻找相似作品」，版本、数据加载时间和方法限制放入「数据与方法」，不在主要使用流程中堆放技术说明。

## 数据与组件

- 搜索、推荐、年份仍调用现有 `/api/search`、`/api/recommend` 和 `/api/meta`；辅助页 `/baseline/`、`/graph/`、`/explain/` 继续可达。
- 卡片和理由由前端展示模块消费 `ranking.results`、`seed_contributions`、`explanations` 与 `path_catalog`；完整报告只读展示，不重新计算排名。
- 简短理由采用确定性模板，从有正贡献的真实路径选取代表项并绑定对应已选游戏。优先按联合贡献选择主题标签，其次类型、开发商；模板只说「与《X》共同包含标签 Y」或「与《X》来自同一开发商 Z」。联合推荐不会把仅部分游戏共有的标签说成所有游戏共同，不推断未验证的玩法或情绪。
- 没有正贡献路径时显示「当前条件下可解释的相似依据较少」，不生成虚构理由，不把分数变成「喜欢概率」或百分比匹配度。
- Steam 详情由已验证的数值 appid 构造官方商店链接，外链新窗口打开并加 `noopener noreferrer`。
- 封面通过真实 appid 对应的 Steam CDN 地址尝试加载，仅用于装饰，不作为评分输入；懒加载、固定比例、图片加载失败显示游戏名称占位。服务器 CSP 仅增加所需图片域名的 `img-src`，其他限制保持。无网络时推荐与解释照常使用。
- 既有标签英文名保留；本轮不建立未经校验的大规模翻译表，不增加大模型接口或登录系统。

## 状态与可访问性

- 没有搜索结果：说明未找到并允许换名称；不合格结果说明资料不足等既有原因，不能添加。
- 没有推荐结果：说明可调整年份或所选游戏，不补充假热门结果、不自动放宽条件。
- 请求失败：显示简短错误和重试入口；详情缺失明确说明，不能把空内容伪装成加载成功。
- 使用语义化表单和按钮、明确 label、键盘焦点、状态播报；展开按钮绑定具体卡片。图片失败和长标题不造成横向溢出。避免卡片嵌套交互和颜色作为唯一提示。

## 验收

1. 对同一输入，原版与新版推荐 appid 顺序、分数、路径与原始来源一致；展示变化可改变 view_version，算法不变。
2. 对真实单游戏、多游戏、年份查询逐项检查卡片与原报告一致；每条简短理由能追溯到对应正贡献路径，权重零的共享事实不作为推荐依据。
3. 浏览器检查桌面与手机布局，以及中文/别名搜索、添加/移除/替换、最多三款、年份筛选/清空、查询取消/重试、旧响应失效、空结果和图片失败。
4. 保留详情路径交互及辅助页入口；键盘可操作，长标题与恶意文本使用安全文本节点呈现。
5. 运行相关现有契约检查，新增测试仅覆盖理由与实际路径一致、联合归属、无依据和图像失败等实质风险；不以测试数量作为效果指标。
6. 完成后提供真实页面地址、桌面/手机截图、新版本交付包与校验摘要。设计草图、运行验证与推荐效果证据分开记录。
