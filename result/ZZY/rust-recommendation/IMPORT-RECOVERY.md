# 导入中断后的恢复

导入先在同目录构建独立 staging 数据库，并完整回放快照事实。每个目标使用
`<目标去扩展名>.sqlite.import.lock/` 独占锁；摘要文件先发布，数据库文件最后以硬链接发布。
已有数据库和摘要均不覆盖。普通导入错误自动释放本进程的锁；强杀或断电可能保留锁和 staging 文件。

1. 先确认针对该目标的导入进程已经退出。不能删除活跃进程的锁。
2. 若数据库与 `.sqlite.sha256` 均存在，运行 `achievement-recommendation-rust verify --db <目标>`。
   验证通过后，只清理中断进程遗留的锁目录、带该进程 PID 的 `.staging` 文件和对应临时 `.sha256`。
   再次 import 会校验绑定并复用；绑定不同则明确拒绝，应指定新数据库路径。
3. 若数据库不存在、仅最终摘要存在，说明中断发生在数据库发布前。确认没有活跃导入后，
   清理该孤立摘要、该目标的锁及中断进程 staging 文件，再次执行 import。
4. 若数据库存在但摘要缺失或校验失败，不要直接生成新摘要或覆盖数据库。保留故障文件，
   改用新输出路径重新从完整冻结快照导入，验证新数据库后再切换服务。

staging 文件全部在目标数据库同目录；清理应限定到确认中断的目标和 PID，不能批量删除其他版本。
服务只打开最终数据库，使用只读连接；不完整发布不会通过启动时的摘要与完整性校验。
