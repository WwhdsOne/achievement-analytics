## 内存与体积实测

本机 ARM64 / Docker Linux；同一冻结数据、1 CPU。Python 容器内存上限 4 GiB，Rust 256 MiB。GiB/MiB 按 1024 进制；表中的磁盘 MB 按十进制。

| 指标 | 原 Python | Rust 磁盘版 |
|---|---:|---:|
| 就绪后空闲进程 RSS | 约 1.42 GiB | 约 2.3 MiB |
| 请求结束后进程 RSS | 约 1.56 GiB | 约 11.6 MiB |
| 4 客户端并发的 Docker 工作集峰值 | 约 1.70 GiB | 约 156.4 MiB |
| 串行单次推荐 | 0.65–1.55 秒 | 2.48–3.41 秒 |
| 启动到接口就绪 | 21.2 秒 | 13.2 秒 |
| ARM64 已展开镜像磁盘占用 | 约 385 MB | 约 3.98 MB |

**12 MiB 是进程 RSS，不能说整个容器只占 12 MiB。** Docker 工作集还包括部分活跃文件缓存及内核开销。Rust 包含可回收文件缓存的 cgroup 总用量最高达到 256 MiB 上限，正常完成、未 OOM；本次请求后空闲工作集约 127.5 MiB。文件页缓存由操作系统管理，并非应用把整张数据库常驻内存。[Docker 统计口径](https://docs.docker.com/reference/cli/docker/container/stats/)

这是一次真实请求基线，不是吞吐压测。两版内存限制不同，Rust 以节省内存为优先，4 个并发客户端在服务内排队；不能把耗时差异单独归因为语言。线上 AMD64 的内存和耗时还应在部署后观察。

完整记录在忽略目录 `build/rust-memory-benchmark-20261020.json`；对照 Python 记录在 `../build/deploy/python-memory-benchmark-20261020.json`。
