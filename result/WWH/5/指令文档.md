# 指令文档（发给模型的提示词原文）

本文件收录**实际发给模型的指令原文**，与代码逐字一致，方便不改 Python 就能读和改。
提示词写在 [wwh5/deepseek.py](./wwh5/deepseek.py) 的 `classification_messages()` 与 `story_messages()`，
版本号是 `PROMPT_VERSION = "wwh5-ds-v3"`。请求的传输格式与预期返回见 [api-contract.md](./api-contract.md)。

## 1. 分类指令（system）

每款游戏按 ≤40 个成就分批调用，这是每一批都发的 system 消息：

```text
Return one valid json object, no markdown. Classify every supplied achievement ID exactly once. primary_category enum main/side/collection/challenge/other/uncertain; scope base/dlc/uncertain; requires_multiplayer boolean or null. Derive gameplay/theme/presentation/player_mode dimensions as lists of labels. Confidence is a number [0,1]. Every label has evidence and uncertainty text. gameplay is a CLOSED ENUM, not free text: it must be nonempty and every entry must be exactly one of action/adventure/rpg/strategy/simulation/puzzle/platformer/racing/sports/survival/rhythm/casual/other/uncertain. Never copy store tags into gameplay — values such as sandbox, crafting, building, exploration or open world are NOT enum members; map that tag to the closest enum value (e.g. survival, simulation, adventure) or use other. theme/presentation/player_mode are free text and may keep the original tag wording. Put the PRIMARY gameplay first, others secondary. All dimension lists have unique labels; use uncertain gameplay rather than an empty list. Use supplied achievement display text and tags and your uncertain model knowledge; disclose uncertainty. Do not invent citations, URLs, or claims of human validation. IDs are surrogate keys, NOT story order. Use uncertain when evidence is weak; multiplayer is an independent attribute, not a category. Game dimensions are authoritative from the first batch; if supplied, repeat them exactly. Reminder: gameplay may contain ONLY enum values from the list above. Output json example: {"achievements":[{"confidence":0.5,"evidence":"supplied text","id":"input-id","primary_category":"uncertain","requires_multiplayer":null,"scope":"uncertain","uncertainty":"explain"}],"game_dimensions":{"confidence":0.5,"evidence":"supplied text","gameplay":["uncertain"],"player_mode":[],"presentation":[],"theme":[],"uncertainty":"explain"}}
```

逐句的意思：

| 指令句子 | 约束 |
|---|---|
| `Return one valid json object, no markdown` | 输出必须是纯 JSON，不能有 ``` 代码块包裹 |
| `Classify every supplied achievement ID exactly once` | 输入里的 ID 不许多、不许漏、不许重复 |
| `primary_category enum …` | 成就主类只能取六个值之一 |
| `scope base/dlc/uncertain` | 本体 / DLC / 不确定 |
| `requires_multiplayer boolean or null` | `null` 表示不确定；这是**独立属性**不是类别 |
| `Derive gameplay/theme/presentation/player_mode … as lists of labels` | 游戏维度是四个字符串列表；**只有 gameplay 是闭集**，另三个是自由文本 |
| `Confidence is a number [0,1]` | 自报置信度，**不是**经验证的准确率 |
| `Every label has evidence and uncertainty text` | 每条都要给依据和不确定说明 |
| `gameplay is a CLOSED ENUM, not free text …` | 玩法必须非空，且每个值只能取固定 14 词表之一 |
| `Never copy store tags into gameplay — values such as sandbox, crafting, building, exploration or open world are NOT enum members` | **不许把商店标签直接抄进玩法**；要映射到最接近的枚举值，或填 `other` |
| `theme/presentation/player_mode are free text and may keep the original tag wording` | 这三个维度允许保留标签原词 |
| `Put the PRIMARY gameplay first` | **列表首位 = 主玩法**，分析按它分组 |
| `All dimension lists have unique labels` | 同一列表内不许重复 |
| `use uncertain gameplay rather than an empty list` | 判断不出来也要填 `uncertain`，不许留空 |
| `Use supplied … and your uncertain model knowledge` | 只能用给它的文本 + 模型知识 |
| `Do not invent citations, URLs, or claims of human validation` | **不许编引用/链接，不许声称经过人工验证** |
| `IDs are surrogate keys, NOT story order` | 防模型按 ID 大小当剧情先后 |
| `Game dimensions are authoritative from the first batch; if supplied, repeat them exactly` | 第二批起带上的维度必须原样重复 |
| `Reminder: gameplay may contain ONLY enum values from the list above` | 结尾再强调一次，防长指令里被忽略 |

> 最后那句 `Output json example: …` 是 few-shot 示例，由程序用 `canonical()` 序列化后拼上去，
> 所以示例里的键是**按字母序**排的。

## 2. 分类指令（user）

user 消息是紧凑 JSON（键排序、中文不转义）。这是 Hollow Knight 的实例：

```json
{"achievements":[{"description":"击败假骑士","display_name":"False Knight","id":"763"},{"description":"","display_name":"Steel Heart","id":"810"}],"localized_title":"空洞骑士","tags":["Metroidvania","Difficult"],"title":"Hollow Knight"}
```

**只发这四类字段**：`title` / `localized_title` / `tags` / `achievements[{id, display_name, description}]`。
没有描述时发 `""` 而不是 `null`。

**刻意不发**：`percent`（完成率）、`review_count`、RAWG 通关/弃坑数、成就 `position`。
这些是**结果变量**——发了模型会按「解锁率低 = 主线」倒推，而不是真的读文本判断。

第二批起会多一个 `authoritative_game_dimensions` 字段，内容是第一批返回的游戏维度，
用来保证同一款游戏所有批次用同一套维度标签。

## 3. 主线排序指令（system）

分类全部完成后，把该游戏**所有被判为 `main` 的成就**一次性送进去：

```text
Return valid json only. These are ALL main-story candidates for one game. Select global ordered checkpoints by narrative prerequisites, never by ID order. stage enum start/early/middle/late/end; route common/branch. requires_start means this checkpoint necessarily requires the chosen start. Choose at most one explicit start and one unified common ending; if separate endings cannot be represented by one achievement, unified_ending=false. Never merge/sum alternative endings. If no defensible linear story exists (sandbox/live service etc.), return empty checkpoints and unified_ending=false. Select only supplied IDs, each at most once; omission is allowed. Confidence number [0,1], evidence text, disclose uncertain model knowledge. No fake citations or human-validation claims. The complete candidate set is supplied in this ONE call. json example: {"checkpoints":[{"confidence":0.5,"evidence":"supplied text","id":"input-id","requires_start":false,"route":"common","stage":"start"}],"confidence":0.5,"evidence":"supplied text","uncertainty":"explain","unified_ending":false}
```

| 指令句子 | 约束 |
|---|---|
| `These are ALL main-story candidates for one game` | 候选一次给全，防止分批各自编顺序 |
| `Select global ordered checkpoints by narrative prerequisites, never by ID order` | **按剧情前置关系排序，不按 ID** |
| `stage enum start/early/middle/late/end` | 剧情阶段 |
| `route common/branch` | `common` 才进公共曲线；`branch` 不参与 |
| `requires_start means … necessarily requires the chosen start` | 后续节点是否必经入门 |
| `Choose at most one explicit start and one unified common ending` | 最多一个入门、一个统一结局 |
| `if separate endings cannot be represented by one achievement, unified_ending=false` | 多结局无法用一个成就代表时必须置 false |
| `Never merge/sum alternative endings` | **绝不把多个结局合并或相加** |
| `If no defensible linear story exists … return empty checkpoints` | 沙盒/服务型游戏返回空，不硬凑 |
| `Select only supplied IDs, each at most once; omission is allowed` | 只能用给定 ID，允许省略 |
| `The complete candidate set is supplied in this ONE call` | 强调不要分批 |

主线调用的 user 消息结构与分类相同，只是 `achievements` 里只放主线候选。

## 4. 枚举与固定词表

改了这些词表就等于改了模型的取值空间，必须同步改校验函数（见 api-contract.md 第 7 节）。

| 名称 | 取值 |
|---|---|
| 成就主类 `primary_category` | `main` `side` `collection` `challenge` `other` `uncertain` |
| 内容范围 `scope` | `base` `dlc` `uncertain` |
| 剧情阶段 `stage` | `start` `early` `middle` `late` `end` |
| 路线 `route` | `common` `branch` |
| 玩法 `gameplay`（14 词，首位为主玩法） | `action` `adventure` `rpg` `strategy` `simulation` `puzzle` `platformer` `racing` `sports` `survival` `rhythm` `casual` `other` `uncertain` |
| 题材 / 表现形式 / 单人多人 | 自由文本标签，无固定词表 |

## 5. 字段含义

### 分类返回的字段

| 字段 | 含义 |
|---|---|
| `game_dimensions.gameplay` | 固定粗分类，**首位是主玩法**；主分析按它分组 |
| `game_dimensions.theme` | 题材维度，可多值，与玩法独立 |
| `game_dimensions.presentation` | 视觉/呈现维度，判断不了可以标 `uncertain` |
| `game_dimensions.player_mode` | 单人/多人归纳，保留不确定 |
| `achievements[].primary_category` | 成就主类，**只选一个**；DLC、联机分字段另存 |
| `achievements[].scope` | 本体 / DLC / 不确定 |
| `achievements[].requires_multiplayer` | 是否必须联机；`null` 表示不确定 |
| `confidence` | 模型自报置信度 0～1，**不是**真实准确率，不进任何"精度"指标 |
| `evidence` | 描述或名称里的文本依据；只能靠模型知识时要说明 |
| `uncertainty` | 不确定的原因；**不许编造外部引用** |

一个成就若同时像主线和可选内容（例如分不清主线 Boss 和可选 Boss），要求标 `uncertain`，
**不许按解锁率高低倒推**。

### 主线返回的字段

| 字段 | 含义 |
|---|---|
| `checkpoints[]` | 有序剧情节点；不要求每个 main 成就都被选为节点 |
| `checkpoints[].id` | 引用本游戏已判为 `main` 的候选 ID |
| `checkpoints[].stage` / `route` | 阶段 / 公共主线或分支（分支不进公共曲线） |
| `checkpoints[].requires_start` | 是否必然要求经过所选入门节点 |
| `unified_ending` | 是否存在代表一般通关的统一结局节点 |
| `confidence` / `evidence` | 节点与整体的判断置信度和依据 |

**候选 ID 顺序、数据库 `position`、解锁率排序都不能当剧情顺序。**
可选内容、DLC、联机、重复周目不能默认为公共必经节点；没有证据支持统一结局时，
退出通关比例比较（不要硬算）。

## 6. 改提示词时的注意事项

⚠️ **改了指令原文必须同时升 `PROMPT_VERSION`**。

原因：`input_hash` 是 messages 的哈希，改了指令文本它就会变，所以**旧记录不会**被误复用
（不会静默沿用旧标注）——但 `prompt_version` 没变的话，`active_annotation` 也不会报警，
库里会混进「用旧指令标的」和「用新指令标的」两批，事后无法区分。所以升版本号是硬要求。

另外 `response_format` 是 `json_object`，DeepSeek 要求提示词里出现 "json" 字样——
两段指令里都有，别在改写时删掉。

⚠️ **内容校验失败目前也会重试 3 次**。`temperature=0` 且 messages 没变时，三次产出是同一类错误，
重试基本是白花钱（v2 那次在 Terraria 上白烧约 1.1 万 completion token）。所以改完指令要
**先小样本验证再放全量**，别直接开跑 1000 款。
